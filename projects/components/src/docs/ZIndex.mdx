# Z-index de overlays

Cómo se apilan menús, selects y datepickers respecto al chrome de la app.

El **sidebar** va por encima del overlay. El **header** y las **migas** van por debajo: si no, un desplegable abierto junto a la cabecera queda tapado.

Demo viva: **Overlays → Nested scroll**. Instalación del paquete: **Instalación**.

---

## Por qué el top-layer no es el default en página

En Angular 22, CDK Overlay usa por defecto la Popover API (`usePopover: true`). Eso sube el panel al **top-layer** del navegador: queda por encima de **cualquier** `z-index`, incluido el sidebar.

En producto (shell 100dvh, sidebar `position: fixed`) el menú no debe tapar el sidebar. Tampoco debe quedar bajo el header sticky. En página, el panel anclado sigue en z-index `1000` (encima del header, debajo del sidebar, fuera del top layer).

Si el trigger está dentro de un diálogo, confirm modal o toast, el panel entra en el top layer y se pinta encima de ese modal. El z-index global no cambia.

---

## Capas (contrato)

De abajo hacia arriba:

| Capa | z-index | Qué entra |
| ---- | ------- | --------- |
| Contenido de página | `auto` | card, tabla, `overflow: auto` |
| Header / migas | **`< 1000`** (Wiloc: **`10`**) | topbar sticky, `wi-breadcrumb` |
| Overlay anclado en página | **`1000`** | `wi-menu`, `wi-select`, datepicker / date-range, filtros y visibilidad de `wi-table`, popover, tooltip, confirm-popup |
| Sidebar | **`> 1000`** (Wiloc: **`1100`**) | menú lateral `position: fixed` |
| Top-layer (Popover API) | por encima de cualquier z-index | `wi-dialog`, confirm modal, toast. Un panel anclado cuyo trigger está dentro entra aquí y se pinta encima de ese modal |

En página el menú **sí** se pinta encima de una card, de un recuadro con overflow y del header / migas (si no, el desplegable queda tapado). **No** se pinta encima del sidebar si este va a `1100`. Dentro de un diálogo, confirm modal o toast, el panel entra en el top layer y queda encima de ese modal. El z-index global sigue en `1000`.

---

## Qué tiene que hacer la app

Header / migas y sidebar **no** comparten z-index:

```css
.app-header {
  position: sticky;
  top: 0;
  z-index: 10; /* sobre el contenido que hace scroll; bajo el overlay 1000 */
}

.app-sidebar {
  position: fixed;
  z-index: 1100;
}
```

- No parchees `Overlay` ni pongas `cdkScrollable` en cada contenedor.
- No subas el z-index de los paneles anclados por encima del sidebar.
- No pongas el header / las migas a `1100` (ni a ningún valor `≥ 1000`): taparían el desplegable.
- No pongas `isolation: isolate` ni un `z-index` alto en cards / shells de contenido: crearían un stacking context y el panel (portal a `body`, `1000`) puede quedar debajo o “salir” raro.

---

## Scroll anidado

Select, menú, tooltip y filtros de tabla **cierran** al hacer scroll fuera del panel (`overflow: auto | scroll` interno o ventana). Datepicker, date-range, popover y confirm-popup **siguen** al trigger (reposicionan). Scroll dentro de la lista del panel no cierra.

Compruébalo en **Overlays → Nested scroll**: sidebar a `1100`, header a `10`. Abre Acciones o un filtro y haz scroll: el menú se cierra. Abre el datepicker y haz scroll: el calendario sigue pegado.

---

## Qué no mezclar

| Sí | No |
| -- | -- |
| Menú / select / datepicker en página a `1000`, fuera del top layer | Subir el z-index global por encima del sidebar |
| Panel anclado dentro de un diálogo en el top layer, encima de ese modal | Dejar ese panel debajo del diálogo |
| Sidebar a `1100` | Sidebar sin z-index (el menú lo tapa) |
| Header / migas a `10` | Header / migas a `1100` (tapan el desplegable) |
| Dialog / toast en top-layer | Esperar que un menú de la página tape el dialog |

---

## Autocompletado nativo de `wi-input`

El desplegable de **autocompletado del navegador** no es un overlay CDK. Se ancla al viewport: si el input está en un `overflow: auto` y haces scroll interno, **se despega** del campo. No se puede reposicionar desde la librería.

En filtros de `wi-table` va `autocomplete="off"`. En cualquier `wi-input` dentro de un shell con scroll interno, pasa `autocomplete="off"` (o un token concreto tipo `username`) si no quieres esa lista nativa.

---

## Dónde está en el código de la lib

La librería inyecta el stacking CDK (`z-index: 1000` en `.cdk-overlay-container` / pane) al cargar un overlay anclado. Opcional en la app: `@import '@wldeveloperapps/ui/styles/overlay.css'`.
