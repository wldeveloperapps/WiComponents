# Instalación de `@wldeveloperapps/ui`

Guía para montar la librería en una **aplicación Angular consumidora**. Corte actual: **`0.1.0-alpha.6`** (API experimental).

Referencia runnable: `apps/e2e-consumer` (consume el `.tgz`, no el source del monorepo).

Otras páginas de este apartado:

- **Tema** — estilos: CSS global, PostCSS, `@theme`, `.wi-dark`
- **Z-index** — apilamiento: overlay `1000`, header/migas `10`, sidebar `1100`, top-layer
- **I18n** — providers, Transloco (`assets/i18n`) e inputs de copy
- **MCP** — `@wldeveloperapps/ui-mcp` en Cursor / VS Code

---

## Requisitos

| Pieza               | Versión / notas                                                   |
| ------------------- | ----------------------------------------------------------------- |
| Angular             | 22 (`@angular/core`, `common`, `forms`, `cdk`, `aria`)            |
| Tailwind CSS        | v4 (peer opcional; las apps Wiloc lo usan)                        |
| `@spartan-ng/brain` | peer de comportamiento; **no** importar en plantillas de producto |
| `clsx`, `rxjs`      | peers                                                             |
| `tw-animate-css`    | peer opcional (animaciones de overlays)                           |

La app **no** debe importar Helm (`@spartan-ng/helm`) ni tipos `Brn*` cuando exista equivalente en `@wldeveloperapps/ui`.

---

## 1. Instalar el paquete

El paquete vive en **GitHub Packages** (`https://npm.pkg.github.com`), no en npmjs.

En el `.npmrc` de la app:

```
@wldeveloperapps:registry=https://npm.pkg.github.com
```

```bash
pnpm add @wldeveloperapps/ui@0.1.0-alpha.6
```

En CI de la app (mismo org): `permissions: packages: read` y `NODE_AUTH_TOKEN: ${{ secrets.GITHUB_TOKEN }}` en `pnpm install`. Da acceso al repo consumidor en GitHub → Package `@wldeveloperapps/ui` → Package settings → Manage Actions access.

Artefacto local (opcional, smoke sin registry):

```bash
# en el repo wi-components
pnpm pack:lib

# en la app (el nombre lo fija `pnpm pack`: scope-name-version.tgz)
pnpm add ./wldeveloperapps-ui-0.1.0-alpha.6.tgz
```

Instala también los peers que la app aún no tenga:

```bash
pnpm add @angular/aria @angular/cdk @angular/forms @spartan-ng/brain clsx tw-animate-css
pnpm add -D tailwindcss @tailwindcss/postcss
```

PostCSS (Tailwind v4):

```json
{
  "plugins": {
    "@tailwindcss/postcss": {}
  }
}
```

Registra `src/styles.css` en `angular.json` → `architect.build.options.styles`.

## 2. Estilos que necesita la app

Detalle (archivos, CSS completo, `@theme`, coexistir con PrimeNG): página **Tema**.

| Qué                          | Dónde                                                                      |
| ---------------------------- | -------------------------------------------------------------------------- |
| Tokens + Tailwind + `@theme` | CSS global (`src/styles.css` / `styles.scss`) registrado en `angular.json` |
| PostCSS                      | `postcss.config.json` en la raíz de la app                                 |
| Tabs / toast                 | `@wldeveloperapps/ui/styles/tabs.css` / `toast.css` solo si los usas                 |

**No** importes `@wldeveloperapps/ui/styles/index.css`.

Si la app ya tiene hoja global: **añade** los `@import` de Wiloc; no dupliques Tailwind si ya está.

Mínimo a pegar (el `@theme inline` completo está en **Tema**):

```css
@import '@spartan-ng/brain/hlm-tailwind-preset.css';
@import '@wldeveloperapps/ui/styles/tokens.css';
@custom-variant dark (&:where(.wi-dark, .wi-dark *));
@source '../node_modules/@wldeveloperapps/ui/**/*.mjs';
```

## 3. Providers en `app.config.ts`

### Iconos (`provideWiIcons`)

Registra **solo** los glifos que la app importa (tree-shaking). Sin este provider, `<wi-icon>` no pinta nada útil.

```ts
import { ApplicationConfig } from '@angular/core';
import { provideWiIcons } from '@wldeveloperapps/ui/icon';
import { trashOutline, homeOutline } from '@wldeveloperapps/ui/icon/heroicons';

export const appConfig: ApplicationConfig = {
  providers: [
    provideWiIcons({
      home: { outline: homeOutline },
      trash: { outline: trashOutline },
    }),
  ],
};
```

```html
<wi-icon name="home" /> <wi-icon name="trash" label="Eliminar" />
```

### i18n (`provideWi*I18n`)

La librería **no** trae diccionarios. Chrome (calendario, tabla, dialog, toast) va en providers; el copy de cada instancia va en el template.

**Apps con Transloco (Wiloc):** claves `wi.*` en `src/assets/i18n/es.json` y `en.json`; factories en `src/app/locale.ts` (`provideAppWiI18n()`). No metas el `.ts` en `assets/i18n`. Detalle y JSON completo: página **I18n**.

```ts
import { provideAppWiI18n } from './locale';

export const appConfig: ApplicationConfig = {
  providers: [provideTransloco({/* config existente */}), provideAppWiI18n()],
};
```

## 4. Tema oscuro

La librería **no** muta `<html>`. La app aplica o quita `wi-dark`:

```ts
import { WI_DARK_CLASS } from '@wldeveloperapps/ui/core';

document.documentElement.classList.toggle(WI_DARK_CLASS, dark);
```

```html
<html class="wi-dark" lang="es"></html>
```

Overlays portaled a `body` heredan el tema si la clase está en `<html>`.

## 5. Z-index de overlays

Los paneles **anclados al trigger** (select, datepicker, menú, filtros de tabla, popover, tooltip, confirm-popup) **no** van al top-layer del Popover API. Así el sidebar puede taparlos y el header / las migas **no** los tapan.

| Capa | z-index | Qué entra |
| ---- | ------- | --------- |
| Contenido de página | `auto` | card, tabla, `overflow: auto` |
| Header / migas | **`< 1000`** (Wiloc: **`10`**) | topbar sticky, breadcrumbs |
| Overlay anclado | **`1000`** (portal CDK) | menú, select, datepicker, filtros |
| Sidebar | **`> 1000`** (Wiloc: **`1100`**) | menú lateral `position: fixed` |
| Top-layer (Popover API) | por encima de cualquier z-index | dialog, confirm modal, toast |

Contrato para la app:

- Sidebar: `position: fixed` y `z-index: 1100` (o mayor que 1000). El menú **no** debe pintarse encima.
- Header / migas: `z-index: 10` (o cualquier valor `< 1000`). El desplegable **sí** se pinta encima.
- No subas el overlay anclado por encima del sidebar. No hace falta `cdkScrollable` ni parchear `Overlay`.
- Cards y recuadros sin z-index quedan **debajo** del panel (si no, el desplegable se oculta al abrir).
- El panel sigue al trigger si el scroll es de un `overflow: auto|scroll` interno.

Demo: Storybook **Documentation → Z-index** y **Overlays → Nested scroll**; `apps/e2e-consumer` (sidebar 1100, header 10).

## 6. Toast (si lo usas)

1. Importa `@wldeveloperapps/ui/styles/toast.css`.
2. Monta `<wi-toast />` **una vez** en el root.
3. Dispara con `wiToast` / `inject(WiToast)`.

```html
<wi-toast theme="auto" /> <router-outlet />
```

## 7. Imports canónicos

Entry points públicos. Nunca Spartan, nunca rutas `src/`:

```ts
import { WI_DARK_CLASS } from '@wldeveloperapps/ui/core';
import { WiButtonDirective } from '@wldeveloperapps/ui/button';
import { WiInputComponent, WiSelectComponent } from '@wldeveloperapps/ui/forms';
import { WiDialogComponent, WiToastComponent } from '@wldeveloperapps/ui/overlays';
import { WiTableComponent } from '@wldeveloperapps/ui/data-display';
import { WiTabsComponent } from '@wldeveloperapps/ui/navigation';
import { provideWiIcons, WiIconComponent } from '@wldeveloperapps/ui/icon';
import { trashOutline } from '@wldeveloperapps/ui/icon/heroicons';
```

| Entry                      | Qué incluye (resumen)                                        |
| -------------------------- | ------------------------------------------------------------ |
| `@wldeveloperapps/ui/core`           | `WI_DARK_CLASS`, tokens, `hlm` (merge de clases)             |
| `@wldeveloperapps/ui/button`         | `button[wiButton]`, `a[wiButton]`                            |
| `@wldeveloperapps/ui/forms`          | input, select, checkbox, switch, datepicker, listbox, otp, … |
| `@wldeveloperapps/ui/overlays`       | dialog, menu, popover, tooltip, toast, confirm, speed-dial   |
| `@wldeveloperapps/ui/data-display`   | table, card, chip, spinner, skeleton                         |
| `@wldeveloperapps/ui/navigation`     | tabs, stepper                                                |
| `@wldeveloperapps/ui/icon`           | `WiIcon`, `provideWiIcons`                                   |
| `@wldeveloperapps/ui/icon/heroicons` | glifos (imports individuales)                                |

## Qué no hacer

- Importar `@spartan-ng/helm`, `@spartan-ng/brain` o tipos `Brn*` en plantillas de producto.
- Usar `@wldeveloperapps/ui/styles/index.css` (Storybook).
- Activar dark mode con `.dark` o `data-theme` (el contrato es `.wi-dark`).
- Importar `heroicons` / PrimeIcons; el catálogo es `@wldeveloperapps/ui/icon/heroicons`.
- Esperar diccionarios ES/EN dentro de la librería.
- Hardcodear datos de producto en los componentes: la app los aporta por inputs / proyección.
- Poner menús anclados en top-layer ni subir su z-index por encima del sidebar (`1100`).
